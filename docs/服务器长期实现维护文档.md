# Algorithms Server 维护文档

## 1. 服务职责

Server 提供算法目录、异步执行和运行状态查询能力。

Server 与桌面客户端共享：

- ModuleRegistry
- 领域结构和算法实现
- ExecutionRuntime
- ExecutionScheduler
- EventEnvelope
- Statistics / Recording

服务端不依赖 JavaFX、ViewState、Reducer 或动画播放逻辑。

## 2. 入口与主要组件

应用入口：

```text
com.majortom.algorithms.server.AlgorithmsServerApplication
```

主要组件：

```text
AlgorithmsController
AlgorithmExecutionService
AlgorithmExecutionServiceImpl
ExecutionScheduler
ExecutionRuntime
RecordingEventSink
ExecutionUnit
```

调用链：

```text
HTTP Request
   ↓
AlgorithmsController
   ↓
AlgorithmExecutionService
   ↓
prepareExecution(...)
   ↓
ModuleRegistry.create(...)
   ↓
ExecutionScheduler
   ↓
ExecutionRuntime
   ↓
RecordingEventSink
```

## 3. HTTP API

Base path：

```text
/api/v1
```

### 3.1 健康检查

```http
GET /api/v1/health
```

响应：

```text
OK
```

### 3.2 算法目录

```http
GET /api/v1/algorithms
```

每个条目提供：

- id
- moduleId
- version
- inputType
- outputType
- capabilities

算法目录由 Server 的 API descriptor 与 Registry 支持的实现共同组成。

### 3.3 提交执行

```http
POST /api/v1/executions
Content-Type: application/json
```

请求结构：

```json
{
  "algorithmId": "quick-sort",
  "input": {
    "values": [5, 1, 8, 3]
  }
}
```

响应是本次执行的 `runId`。

执行提交后立即进入后台 Scheduler。

### 3.4 查询执行

```http
GET /api/v1/executions/{runId}
```

`ExecutionUnit` 包含：

```text
runId
algorithmId
status
duration
totalEventCount
```

状态定义见 `ExecutionState`。

## 4. 算法目录

Server 支持的算法由 `AlgorithmExecutionServiceImpl` 中的 API descriptor 定义。

包括：

### Sort

- insertion-sort
- selection-sort
- quick-sort
- heap-sort

### Maze

- maze-generator-bfs
- maze-generator-dfs
- maze-generator-union-find
- graph-generator-bfs
- maze-pathfinder-astar
- maze-pathfinder-dfs

### Tree

- tree-avl

### Graph

- graph-bfs

### String

- kmp

具体实现仍由 `ModuleRegistry` 根据资源 key 创建。

## 5. 输入转换

HTTP 层使用 `Map<String, Object>` 接收算法输入：

```java
public class ExecutionRequest {
    private String algorithmId;
    private Map<String, Object> input;
}
```

Service 使用 `ObjectMapper.convertValue(...)` 转为窄 DTO 或领域输入。

例如：

```text
JSON
 ↓
GraphBfsRequest
 ↓
MutableGraph<Integer>
 ↓
GraphBfs.traverse(...)
```

以及：

```text
JSON
 ↓
StringSearchRequest
 ↓
MutableString
 ↓
KmpSearch.search(...)
```

HTTP DTO 只负责传输，不作为 core 或 algorithms 的公共接口。

## 6. Registry 使用

Server 通过：

```java
private static final ModuleRegistry MODULES = ModuleLoader.load();
```

加载生产实现。

算法创建示例：

```java
MODULES.create("algorithm.array.Integer.quick-sort", AbstractIntegerSort.class);
```

添加 Server 算法入口前，应先保证对应实现已经在：

```text
META-INF/algorithms.factories
```

注册。

## 7. 执行调度

Server 使用 bounded `ExecutionScheduler`：

```java
ExecutionScheduler.bounded("algorithm-executor-", 10, 20, 100)
```

含义：

- core threads: 10
- max threads: 20
- queue capacity: 100

Scheduler 是 Service 生命周期的一部分，并在 Spring Bean 销毁时关闭。

如果需要调整并发，应结合：

- 算法平均运行时间
- 每次运行内存占用
- EventEnvelope 数量
- HTTP 请求峰值

统一调整，而不是在算法内部创建线程。

## 8. Runtime 与 Recording

每次后台执行会创建：

```text
RecordingEventSink
ExecutionRuntime
ExecutionOperation
```

Runtime 产生统一 EventEnvelope。

执行结束后使用 Recording 统计：

- runtime duration
- total event count
- domain event count
- lifecycle event count
- domain metrics

`ExecutionUnit` 保存对 HTTP 查询有用的摘要状态。

如果需要持久化完整执行历史，适合保存 EventEnvelope / ExecutionRecording，而不是客户端 ViewState。

## 9. 错误处理

执行结果由 Runtime 归一化为：

```text
COMPLETED
CANCELLED
FAILED
```

Server 将对应状态写入 `ExecutionUnit`。

对外 API 的进一步异常规范可以围绕以下方向扩展：

- algorithmId 不存在
- input JSON 无法转换
- 输入参数非法
- Scheduler 队列满
- runId 不存在
- 算法执行失败

建议统一为明确的 HTTP 状态码和错误 DTO。

## 10. 新增 HTTP 算法入口

步骤：

1. 在 algorithms 中实现领域算法。
2. 在 `META-INF/algorithms.factories` 注册。
3. 在 Server 的算法目录加入 descriptor。
4. 根据 JSON 结构增加窄 request DTO（如需要）。
5. 在 `prepareExecution` 中完成 DTO → 领域输入转换。
6. 通过 ModuleRegistry 获取实现。
7. 将具体领域方法包装为 `ExecutionOperation`。
8. 交给 ExecutionRuntime 执行。

示意：

```java
PreparedExecution prepared = new PreparedExecution(
        () -> algorithm.someDomainMethod(domainInput));
```

## 11. 维护边界

Server 层保持以下边界：

- Controller 只处理 HTTP。
- Service 负责编排输入转换和执行提交。
- Registry 决定具体实现。
- Runtime 管理执行生命周期。
- Scheduler 管理执行线程。
- algorithms 保留核心算法逻辑。
- Server 不解释 JavaFX 展示状态。
- HTTP DTO 不进入 core。
