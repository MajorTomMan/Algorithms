# Algorithms V2 系统架构设计

## 1. 总体架构

```text
                       META-INF/algorithms.factories
                                  +
                     ServiceLoader<ModuleDiscovery>
                                  │
                                  ▼
                           ModuleRegistry
                                  │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
              canonical Structure           Algorithm
                    │                           │
                    └───────────┬───────────────┘
                                ▼
                         real mutation
                                ▼
                      factual StructureEvent
                                ▼
                       ExecutionRuntime
                                ▼
                         EventEnvelope
                                ▼
                Timeline / Statistics / Logging
                                │
                                ▼
                         client Reducer
                                ▼
                            ViewState
                                ▼
                    project-owned JavaFX Visualizer
```

V2 的关键边界：

1. `Structure` 是结构事实唯一来源。
2. Algorithm 使用普通领域 API，不显式发 visualization-driving Event。
3. Runtime 负责生命周期、调度、Timeline、Recording，不认识具体算法语义。
4. Reducer 把 factual Event 投影为 UI-neutral ViewState。
5. Visualizer 只读取 ViewState，不读取 live Structure。

## 2. 模块边界

### 2.1 core

负责跨模块基础设施：

- ExecutionEvent / factual structure event contract
- EventEnvelope / EventSink
- ExecutionRuntime / RunControl
- ExecutionScheduler
- ModuleLoader / ModuleRegistry / ModuleDiscovery SPI
- Timeline
- Snapshot 数据契约
- Statistics / ExecutionSummary / ExecutionTiming
- Logging

`core` 禁止依赖 JavaFX、AtlantaFX、Spring 或 algorithms implementation。

### 2.2 algorithms

负责 canonical Structure 与 Algorithm implementation，并提供 Algorithm auto-discovery provider。

`AlgorithmModuleDiscovery` 必须位于 algorithms，因为它需要认识 `Sort`、`TreeAlgorithm`、`GraphTraversal`、`StringSearch`、Maze family；core 只知道 `ModuleDiscovery` SPI。

### 2.3 client

负责：

- JavaFX + AtlantaFX Workbench
- Structure controls
- Reducer / ViewState
- Timeline playback
- family-specific Layout / Geometry / Animation / Visualizer
- Snapshot UI
- Log / Stats presentation

### 2.4 server

负责 headless HTTP 边界与执行。Server 依赖 core + algorithms，不依赖 client。

### 2.5 other

仅保存练习/历史/教材代码，不属于 production registry。历史代码如仍有教学价值，应在 `other` 内自包含或迁移到当前 API，而不是污染 `algorithms/main`。

## 3. Canonical Structure

### 3.1 Array

```text
ArrayStructure<T>
    size/isEmpty/get/set/insert/remove/swap

implementation:
    algorithms.library.basic.Array<T>
```

不暴露 raw array/list。

### 3.2 LinkedList / Stack / Queue

三个 Contract 复用一个 project-owned implementation：

```text
LinkedList<T>
  implements LinkedStructure<T>, StackStructure<T>, QueueStructure<T>
```

ListNode mutable field 为 private，真实 pointer mutation 走 setter 并产生 factual Event。

### 3.3 Tree family

`Tree` 默认含义固定为 **General/N-ary Tree**，不是 BinaryTree/BST。

当前 V2 正式范围：

```text
TreeNode<T>
├── GeneralTreeNode<T>       ordered children
└── BinaryTreeNode<T>        left/right
    └── AVLTreeNode<T>       height/subtree metrics

Tree<T>                      GeneralTreeStructure<T>
AVLTree<T>                   SearchTreeStructure<T>
```

公共 `TreeNode` 只保存所有 Tree 共有的 `id/value`；不再携带 children、left/right、height、subTreeCount、status。ordered children 只存在于 `GeneralTreeNode`，left/right 只存在于 `BinaryTreeNode`，AVL metrics 只存在于 `AVLTreeNode`。

当前未完成：

```text
RedBlackTree / RedBlackTreeNode
canonical HuffmanTree / HuffmanTreeNode
```

它们明确属于 future implementation。旧 `basic/HuffmanTree` 已从 production source 删除，不能据此宣称 Huffman 已完成。

`GeneralTreeStructure` 当前能力：

```java
GeneralTreeNode<T> addRoot(T value);
GeneralTreeNode<T> addChild(GeneralTreeNode<T> parent, T value);
GeneralTreeNode<T> addChild(GeneralTreeNode<T> parent, int index, T value);
T set(GeneralTreeNode<T> node, T value);
boolean remove(GeneralTreeNode<T> node);
void move(GeneralTreeNode<T> node, GeneralTreeNode<T> newParent);
void move(GeneralTreeNode<T> node, GeneralTreeNode<T> newParent, int index);
```

`move` 必须通过 Structure API 执行并维护无环树不变量，不允许 Controller 直接改 children。

### 3.4 Graph

只保留：

```text
algorithms.library.basic.graph.Graph<T>
```

有向性是实例配置。Vertex/Edge 拥有稳定 ID；Graph 持有 adjacency，Vertex 不暴露 mutable neighbors。

### 3.5 HashTable

当前仅保留实现中立的 `HashTableStructure<K,V>` Contract：

```text
size / capacity / containsKey / get / put / remove / entries
```

没有 concrete implementation、没有 Registry registration、没有 bucket/probe/chain 等实现细节进入 Contract。

### 3.6 String

`algorithms.library.basic.String` 是 project-owned mutable String Structure。Contract 暴露 char/range 级领域操作和值视图，不暴露 StringBuilder/raw mutable state。

## 4. Event 语义

执行事实分为三类，不建立每个 Algorithm 独立的 Event hierarchy：

```text
ExecutionEvent
├── StructureEvent    数据真实发生 mutation
├── ObservationEvent  执行过程真实发生但数据没有 mutation
└── RuntimeEvent      Runtime lifecycle
```

### 4.1 StructureEvent

StructureEvent 只回答真实结构变化：Array Inserted/Removed/Updated/Swapped、Tree relationship/value mutation、Graph vertex/edge mutation、Linked relation mutation、String char/range mutation。Algorithm 不伪造 StructureEvent；它调用 Structure API 后由真实 mutation 自动产生事实事件。

### 4.2 ObservationEvent

当前最小 observation contract 只实现真实需要：

```text
Compared(leftRef, rightRef)
Visited(ref)
Examined(fromRef, toRef)
Matched(index, length)
Fallback(fromIndex, toIndex)
Backtracked(ref)
```

ObservationEvent 不描述 UI，也不携带 Runtime metadata。BFS/KMP/Maze pathfinding/Sort compare 在真实发生位置表达 observation，Runtime 添加 envelope metadata。StatisticsContribution 从这些事实贡献 comparisons/nodesVisited/edgesExamined/backtracks 等指标，UI 不猜统计结果。

### 4.3 RuntimeEvent / execution gate

Runtime lifecycle：Started / Paused / Resumed / Completed / Cancelled / Failed。Recording 明确支持 PAUSED，sequence 只在 sink 成功交付后提交。

Live Step gate：checkpoint、StructureEvent、ObservationEvent 共享同一个 permission contract；PAUSED 下一个 permit 只放行一个可观察执行单位。Log/Snapshot 辅助事件可以记录但不消费 Step permit。

## 5. Snapshot 与 reconstruction boundary

Snapshot 是不可变数据契约，不是 mutable Structure，也不是 ViewState。

Structure 模式持有唯一 live editable Structure；Algorithm 模式从当前/保存 Snapshot 构造隔离副本。

Snapshot reconstruction 不应伪装成一系列普通编辑 Event，也不应成为公共 mutable escape hatch。正式入口采用**创建新 Structure**的方式：

```text
Tree.fromSnapshot(GeneralTreeSnapshot)
Graph.fromSnapshot(GraphSnapshot)
AVLTree.fromRestoredRoot(snapshot-reconstructed root)
```

已经取消对现有实例直接替换内部状态的：

```text
Tree.restore(...)
Graph.restore(...)
AVLTree.restore(...)
```

Controller 的 Snapshot Restore 是边界操作：创建新的 live Structure 后替换 Controller 持有的实例；普通 CRUD 无法借此绕过 Structure mutation/Event。

Snapshot 是跨边界数据，不假设天然可信。`Graph.fromSnapshot` 验证 vertex/edge identity、value identity、endpoint 与 parallel-edge 不变量；`Tree.fromSnapshot` 验证 node identity/ID/size；`AVLTree.fromRestoredRoot` 验证 strict BST ordering、node identity、height/subtree metrics 与 balance factor。非法输入直接拒绝，不通过 normalize 静默修复。

## 6. Algorithm I/O、ValueType 与发现

算法保持 family-specific 自然 API，不建立万能 `run(Context)`，也不在 `algorithms` 层维护 `AlgorithmInput / AlgorithmOutput / XxxInput / XxxOutput`。普通 Java 方法签名本身就是算法 I/O Contract：

```java
void Sort<T>.sort(ArrayStructure<T> array);
List<T> GraphTraversal<T>.traverse(GraphStructure<T> graph, T startNode);
List<Integer> StringSearch.search(StringStructure target, java.lang.String pattern);
void AvlTreeCommands.execute(AVLTree<Integer> tree, List<AvlCommand> commands);
GridMaze ArrayMazeGenerator.generate(MazeDimensions dimensions, long seed);
List<GridPoint> ArrayMazePathfinder.findPath(GridMaze maze, GridPoint start, GridPoint goal);
GraphSnapshot<T> GraphMazeGenerator<T>.generate(MazeDimensions dimensions, long seed);
```

真正具有领域意义的 `GridMaze / GridPoint / MazeDimensions / Structure / Snapshot` 正常保留；只有为把真实参数/返回值再包一层而存在的框架 DTO 被删除。

Registry `ValueType` 只描述算法所属的数据值类型，不代表整个输入。允许值固定为：

```text
Integer / Long / Double / Float / Boolean / Character / Byte / Short / String
```

Algorithm discovery：

```text
core.ModuleDiscovery SPI
        ↑ ServiceLoader
algorithms.AlgorithmModuleDiscovery
        ↓
algorithm.<family>.<ValueType>.<algorithm-id>
```

显式 `algorithms.factories` entry 优先覆盖自动发现。

### 6.1 Server I/O boundary

Server transport DTO 不属于 algorithms I/O wrapper，职责边界为：

```text
HTTP JSON
    ↓
Server Request DTO
    ↓
Structure / 普通 Java 参数
    ↓
Algorithm
    ↓
真实 Java 返回值
```

`ExecutionRequest`、`core.runtime.ExecutionResult`、`core.snapshot.*` 保留。Server 的 `prepareExecution` 负责把 HTTP DTO 转成 `Array / Graph / AVLTree / GridMaze / MazeDimensions / GridPoint / StringStructure` 等真实调用参数；算法完成后，Server 再把真实返回值或修改后的隔离 Structure 投影为 HTTP 返回数据。

Server catalog 的 API descriptor 只保存 transport metadata，返回前必须用 ModuleRegistry availability 过滤；Registry 是 implementation truth。Execution scheduler reject 显式映射为 429 且不会留下永久 QUEUED；terminal execution bounded retention；查询结果保留 status/result/failure/duration/statistics/recording identity/event count。HTTP 错误统一为 ErrorResponse：invalid input 400、not found 404、queue full 429、internal preparation failure 500。

## 7. Reducer / ViewState / Visualization

```text
StructureEvent / ObservationEvent
        ↓
      Reducer
        ↓
     ViewState
        ↓
family-specific layout adapter
        ↓
project-owned JavaFX geometry / CSS / animation
        ↓
VisualizationSurface / GestureFX
```

Reducer/ViewState 不依赖 JavaFX/AtlantaFX、不读取 live Structure。Reducer 可以把 factual ObservationEvent 投影成 transient playback state，但不保存算法实现对象。

可视化职责固定为：JavaFX 拥有视觉元素/CSS/动画；AtlantaFX 负责 Workbench UI；GestureFX 负责 viewport；ELK 仅在 client 内作为 transient layout calculator。Array/String/Stack/Queue/LinkedList/Tree/Graph 使用 family-specific ELK adapter；Maze 保留 custom Grid/Canvas Layout。禁止 UniversalGraph/UniversalVisualModel，也不把 ELK model 泄漏到 Structure/Event/Snapshot/ViewState/core/algorithms/server。

ELK async failure 属于 presentation failure：记录错误、保留 last-good geometry、清理 pending request，并允许下一次 topology/size change 重试；不得在 FX Thread 上重新抛异常，更不得修改领域数据“修复”布局。

## 8. Workbench

一个 Workbench、一个 Visualizer 区域、两种互斥模式：

```text
Structure Mode
Algorithm Mode
```

Structure 模式：编辑唯一 live Structure、Snapshot、Structure History。

Algorithm 模式：选择当前/保存 Snapshot，创建 isolated runtime copy；算法执行、取消、回放均不反写 live Structure。

Workbench 的模块、value type、algorithm list 由 `ModuleRegistry` 驱动；未注册类型显示 unavailable，不硬编码假能力。

## 9. Playback / Timeline

Runtime event stream 是权威历史；JavaFX animation 是 presentation。

```text
x1  -> base duration
x8  -> base duration / 8
x16 -> 0 duration, direct snap
scrub -> 0 duration, direct snap
```

因此快速回放不会因为完整 Timeline 而积压无界动画任务。

## 10. Production source closure

`algorithms/main` 不保存重复历史实现。已处理：

```text
SymbolGraph      -> production 删除，示例改用 canonical Graph
CycleList        -> 删除
PolyList         -> production 删除，多项式练习在 other 自包含
旧 basic.KMP     -> 删除，示例改用 KmpSearch
旧 HuffmanTree   -> production 删除，历史练习仅留 other
```

`Bag`、`UnionFind` 等有独立用途、没有复制 canonical family 的代码保留。

## 11. Final verification

Execution Closure 验收阶段使用最小 contract tests 覆盖正式 Runtime / Snapshot / Server contract；验证通过后删除临时测试源码，正式仓库不保留 `src/test`。最终交付继续验证 production build 与 runtime/UI smoke：

```text
完整 Maven reactor clean compile
Pause / Resume recording + replay
sink failure 后 sequence contiguous
PAUSED Live Step 精确放行一个 checkpoint / StructureEvent / ObservationEvent
BFS Visit/Examine、KMP Compare/Fallback/Match、Maze Visit/Backtrack observation
Structure/Observation statistics factual aggregation
Graph/General Tree/AVL Snapshot invariant rejection
Server scheduler reject / bounded retention / result & failure query / HTTP errors
ELK failure containment
JavaFX startup + VisualizationSurface smoke
Snapshot isolation / Timeline deterministic replay
x8 playback scaling / x16 no-animation backlog
```

正式文档以 2026-09-04 Unified Baseline + Execution Closure 为准；完成标准是源码、Registry、Runtime、Server、UI 与文档描述同一事实。
