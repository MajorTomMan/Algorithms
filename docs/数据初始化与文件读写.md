# 数据初始化与文件读写

本篇是 [整体架构说明](ARCHITECTURE.md) 中“数据与结构分离”的具体示例；接口实现见 `core.io`、`algorithms.io`、`structures.graph`。

## 一、为什么“读取数据”不等于“初始化结构”

- **JSON/CSV → Java**：只解决文件格式问题，属于 `AbstractResourceLoader`、`JsonDataCodec`、`CsvDataReader`。
- **Java 业务对象 → 图的拓扑**：读取 `@GraphNodes`、`@GraphEdges`，关联端点，属于 `GraphMappingMetadata` 与 `GraphObjectMapper`。
- **快照 → 真实结构**：`Graph.fromSnapshot` 创建实例，`graph.initialize(snapshot)` 整体替换已有实例。
- **真实结构 → 可视化**：改变结构后发布 `GraphStructureEvent.Reset`；Reducer 根据事件计算视图状态，UI 不靠手工刷新数据重建真值。

这种分层避免给一个通用资源读取器不断增加 City、Road、Region 等特定业务规则。

## 二、资源文件怎么组织

```text
algorithms/src/main/resources/
└── graph/regions/demo/
    ├── region.json     # 区域名称和资源位置
    ├── cities.json     # 城市实体
    └── roads.json      # 道路实体
```

`region.json` 当前是资源清单：

```json
{
  "name": "珠三角示例路网（模拟数据）",
  "cities": "graph/regions/demo/cities.json",
  "roads": "graph/regions/demo/roads.json"
}
```

`cities.json` 使用 `City` 字段：

```json
[{"id":"sz","name":"深圳"},{"id":"gz","name":"广州"}]
```

**注意当前模型的端点类型**：

```java
public record Road(String id, City from, City to,
                   double distance, boolean bidirectional) {}
```

所以 `roads.json` 直接解成 `List<Road>` 时，`from/to` 必须是可解成 `City` 的对象：

```json
[{
  "id": "g4",
  "from": {"id":"sz","name":"深圳"},
  "to": {"id":"gz","name":"广州"},
  "distance": 138,
  "bidirectional": true
}]
```

上面是**结构形状示例**，不是实际道路距离的可靠地图数据。

如果把 `from` 改为 `"sz"`，Jackson 不会自动去 `cities.json` 查找对应 City；应由业务层按 ID 显式关联，或另行定义可信的引用解析机制，不能要求基础加载器猜测。

## 三、资源门面和泛型参数

```java
List<City> cities = AlgorithmResourceLoader.load(
    "graph/regions/demo/cities.json",
    new TypeReference<List<City>>() {}
);
List<Road> roads = AlgorithmResourceLoader.load(
    "graph/regions/demo/roads.json",
    new TypeReference<List<Road>>() {}
);
```

`load(..., TypeReference<T>)` 的 `T` 是**整个 JSON 返回类型**；`loadCsv(..., TypeReference<T>)` 的 `T` 是**每一行 CSV 的类型**，方法返回 `List<T>`。

路径是相对 classpath 的资源路径，不是操作系统任意文件路径；加载器拒绝 `..`、空路径段和反斜杠等非法输入，读取后负责关闭 InputStream。调用方获得的是普通对象，而非带 UI 依赖的结构。

## 四、数据转换成图

```java
Region region = new Region("中国", cities, roads);

Graph<City> source = Graph.from(
    GraphDirection.DIRECTED, City.class, region
);
```

`Region.cities` 通过 `@GraphNodes` 标记顶点；`Region.roads` 用 `@GraphEdges` 标记边。

映射器分两个阶段：先收集顶点，再遍历边。边端点如果不是 Region 中的同一个 City 对象，仍可以利用 `City.@ValueId` 的业务键找到已收集的顶点。真实的 `Vertex.id()`、`Edge.id()` 由结构分配，不能等同于 `City.id()`。

要把图写入框架**已存在**的 GraphStructure：

```java
graph.initialize(source.snapshot());
```

`initialize` 不是偷偷替换引用：它先在临时图验证快照，成功后替换内部数据，再发布一次 Reset 事件。若输入图与已有图的 directed/undirected 方向不一致，将被拒绝；初始化不会修改方向。

## 五、和 @AlgorithmInitialize 的关系

```java
@Algorithm(id = "shortest-path", name = "最短路径",
    types = {City.class}, structure = GraphStructure.class)
public class ShortestPath {

    @AlgorithmInitialize
    public void init(GraphStructure<City> graph) {
        // 读取 Cities + Roads，创建 Region / Graph
        // graph.initialize(source.snapshot());
    }

    @AlgorithmEntry
    public void execute(GraphStructure<City> graph) {
        // 真正算法逻辑；当前示例尚未实现
    }
}
```

这两个方法由 `AlgorithmDescriptor.invoke` 调用；使用同一算法实例和结构对象。初始化**每次运行**执行，不是应用启动一次的 hook。初始化发出的结构事件会进入同一次算法会话与回放历史。

## 六、常见问题与边界

| 现象 | 优先检查 |
| --- | --- |
| 找不到资源 | 文件是否已在 Maven `src/main/resources` 内打包、路径是否正确 |
| Jackson 提示 `City` 类型不匹配 | `Road.from/to` 是否还是字符串而非 City 对象 |
| 图引用了不存在的城市 | `Region.cities` 是否包含道路端点对应的 `@ValueId` |
| 初始化方向不匹配 | `graph.direction()` 与构建图的方向是否一致 |
| 算法没有出现在图选择器 | `@Algorithm` 是否已编译、`City` 是否注册、当前顶点类型是否为 City |
| 初始化成功但没看到算法步骤 | `@AlgorithmEntry` 是否真正发布算法事件；当前 ShortestPath 仍为空实现 |
