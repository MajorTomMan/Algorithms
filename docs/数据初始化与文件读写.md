# 数据初始化与文件读写

## 原则

所有结构优先使用**已有的类型化 Snapshot** 保存、读取与构造。Snapshot 描述结构状态，`core.io` 只处理数据流，具体结构负责校验与恢复：

```text
文件 ──> FileDataIO / JsonDataCodec ──> Snapshot ──> Structure.fromSnapshot()
程序生成 ──> Structure 操作 / initialize() ──> snapshot() ──> 文件或算法输入
```

不引入与 Snapshot 重复的 `GraphData`、`GraphLink`、`GraphInitializer`、`ArrayInitializer` 或通用 `StructureInitializer`；普通随机/批量输入由应用层先整理为对应 Snapshot，再调用 `structure.initialize(snapshot)`。通用 I/O 层不依赖任何结构。

## 读写 API（位于 core）

`core.io` 属于 `core` Maven 模块，不再作为 `data-io` 单独构建：

- `DataReader<T>`、`DataWriter<T>` 分别负责从 `InputStream` 读取和向 `OutputStream` 写入。
- `DataCodec<T>` 同时包含这两个能力。
- `JsonDataCodec<T>` 通过 Jackson 处理 `Class<T>` 或 `TypeReference<T>` 的 JSON 序列化，并注册 JavaTimeModule 以支持包含 `Instant` 的完整工作区快照。
- `FileDataIO.read/write` 提供基于 `Path` 的便捷访问，并负责打开和关闭文件流。

流由调用者持有时，`JsonDataCodec` 不会主动关闭它。文件写入先序列化到目标同目录的临时文件，再尝试原子替换；如果文件系统不支持原子移动，则退化成普通替换。目标目录必须事先存在。序列化失败时，原文件不会被提前截断，但非原子替换不保证最后一步的原子性。

## 示例：保存并恢复图

```java
import com.fasterxml.jackson.core.type.TypeReference;
import com.majortom.algorithms.core.metadata.GraphDirection;
import com.majortom.algorithms.core.snapshot.GraphSnapshot;
import com.majortom.algorithms.core.io.FileDataIO;
import com.majortom.algorithms.core.io.JsonDataCodec;
import com.majortom.algorithms.structure.graph.Graph;
import com.majortom.algorithms.structure.graph.Vertex;
import java.nio.file.Path;

Graph<Integer> source = new Graph<>(GraphDirection.UNDIRECTED);
Vertex<Integer> a = source.addVertex(1);
Vertex<Integer> b = source.addVertex(2);
source.addEdge(a, b, 5.0);

JsonDataCodec<GraphSnapshot<Integer>> codec =
    new JsonDataCodec<>(new TypeReference<GraphSnapshot<Integer>>() {});

Path path = Path.of("graph.json");
FileDataIO.write(path, source.snapshot(), codec);

GraphSnapshot<Integer> state = FileDataIO.read(path, codec);
Graph<Integer> restored = Graph.fromSnapshot(state);
```

生成节点、边时由结构自动分配 ID。保存的 Snapshot **必须包含 ID**，因为要支持精确恢复与事件回放，读取时不应把原 ID 随机替换。

例如从上面的图保存出的 JSON：

```json
{
  "direction": "UNDIRECTED",
  "vertices": [{"id": 1, "value": 1}, {"id": 2, "value": 2}],
  "edges": [{"id": 1, "fromId": 1, "toId": 2, "weight": 5.0}]
}
```

这里的 ID 仅供示意，实际值取决于当前进程中已分配的对象，不保证从 1 开始。

若未来需要支持**完全不写 ID 的手工 JSON**，可在客户端读取到“节点值 + 连接关系”后自动创建节点、边并调用 `graph.snapshot()`；它属于导入格式的适配逻辑，不应改变 Snapshot 的定义，也不用让核心框架再维护第二套图数据模型。

## 示例：数组与其他结构

```java
import com.fasterxml.jackson.core.type.TypeReference;
import com.majortom.algorithms.core.snapshot.SequenceSnapshot;
import com.majortom.algorithms.core.io.FileDataIO;
import com.majortom.algorithms.core.io.JsonDataCodec;
import com.majortom.algorithms.structure.array.Array;
import java.nio.file.Path;
import java.util.List;

Array<Integer> source = new Array<>(List.of(3, 1, 4));
JsonDataCodec<SequenceSnapshot<Integer>> codec =
    new JsonDataCodec<>(new TypeReference<SequenceSnapshot<Integer>>() {});

FileDataIO.write(Path.of("array.json"), source.snapshot(), codec);
Array<Integer> restored = Array.fromSnapshot(
    FileDataIO.read(Path.of("array.json"), codec));

// 同样可以不换掉对象，直接用快照重置已有结构：
source.initialize(restored.snapshot());
```

两种初始化入口：

```java
// 新建
Graph<Integer> restoredGraph = Graph.fromSnapshot(state);

// 在原实例上批量替换（有向性必须匹配）
source.initialize(state);
```

结构快照初始化协议：



| 结构 | 快照 | 创建 / 原地初始化 |
| --- | --- | --- |
| Array | `SequenceSnapshot<T>` | `Array.fromSnapshot()` / `Array.initialize(snapshot)` |
| LinkedList / Stack / Queue | `SequenceSnapshot<T>` | `LinkedList.fromSnapshot()` / `LinkedList.initialize(snapshot)` |
| Graph | `GraphSnapshot<T>` | `Graph.fromSnapshot()` / `Graph.initialize(snapshot)` |
| General Tree | `GeneralTreeSnapshot<T>` | `Tree.fromSnapshot()` / `Tree.initialize(snapshot)` |
| AVL Tree | `BinaryTreeSnapshot<T>` | `AVLTree.fromSnapshot()` / `AVLTree.initialize(snapshot)` |
| Hash Table | `HashTableSnapshot<K,V>` | `ChainedHashTable.fromSnapshot()` / `ChainedHashTable.initialize(snapshot)` |
| String | `StringSnapshot` | `String.fromSnapshot()` / `String.initialize(snapshot)` |
| Grid Maze | `MazeSnapshot` | `Maze.fromSnapshot()` / `Maze.initialize(snapshot)`（仅网格） |

对于哈希表，Workbench 仍使用 `HashTableStateSnapshot` 保存键值类型元信息，而内部实际表内容使用 `HashTableSnapshot`。

## 正确性

- 文件读取或反序列化失败不会修改当前结构；构造失败时也不应替换工作区原结构。
- 图、树精确恢复时必须验证节点标识、连接关系及不变量。
- 哈希表快照恢复校验桶位置与 key 的哈希映射一致性；数组、链表保持元素顺序。
- `initialize(snapshot)` 不应发出逐元素事件；哈希表的整体状态替换使用单条 `hashRehashed` 事件以保留现有 Reducer 兼容性。
- JSON 读取自定义值类型时需配置 Jackson 能够反序列化该类型。
- `StructureSnapshot<S>` 是工作区保存的额外元数据（时间、模块 ID、值类型），不是另外一种可变结构。
- 当前没有增加 GUI 文件选择按钮；`core.io` 提供 Java API，界面接入是单独的后续工作。
