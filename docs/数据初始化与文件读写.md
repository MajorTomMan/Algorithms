# 数据初始化与文件读写

目标是让“数据来自哪里”和“数据如何进入结构”完全分离。

## 模块关系

```text
JSON / 其他文件 ──> data-io ──> GraphData<T> / List<T>
程序生成 / 随机 ─────────────────┘
                                  |
                                  v
                      StructureInitializer<S, D>
                                  |
                              Graph / Array
                                  |
                         Algorithm / JavaFX
```

- `data-io`：只把字节流转换为 Java 对象，或把 Java 对象转换为字节流。
- `structures`：维护 `StructureInitializer`、`GraphData`、`GraphLink`、`GraphInitializer`、`ArrayInitializer`，不认识 JSON 或文件路径。
- `client`：负责组合两个模块，也继续承接手动/随机输入、执行状态失效和界面重绘。

## GraphData 文件格式

示例 `graph.json`：

```json
{
  "direction": "UNDIRECTED",
  "vertices": [440300, 440100, 440600],
  "edges": [
    { "from": 440300, "to": 440100, "weight": 120.0 },
    { "from": 440100, "to": 440600, "weight": 35.0 }
  ]
}
```

无向边只写一次，初始化器负责双向邻接。这里的权重是算法演示值，不代表真实距离。

图的数据模型不保存运行时 ID。若需要精确恢复节点/边 ID、算法事件回放，应继续使用 `GraphSnapshot`，不要混用两者。

## 从文件读取图、数组

```java
import com.fasterxml.jackson.core.type.TypeReference;
import com.majortom.algorithms.structure.array.Array;
import com.majortom.algorithms.structure.graph.Graph;
import com.majortom.algorithms.structure.graph.GraphData;
import com.majortom.algorithms.visualization.data.StructureDataFiles;
import java.nio.file.Path;
import java.util.List;

TypeReference<GraphData<Integer>> graphType = new TypeReference<>() {};
Graph<Integer> graph = StructureDataFiles.loadGraph(Path.of("graph.json"), graphType);
StructureDataFiles.saveGraph(Path.of("graph-copy.json"), graph, graphType);

TypeReference<List<Integer>> arrayType = new TypeReference<>() {};
Array<Integer> array = StructureDataFiles.loadArray(Path.of("array.json"), arrayType);
StructureDataFiles.saveArray(Path.of("array-copy.json"), array, arrayType);
```

这是一组**程序调用接口**，暂未增加图形界面的文件选择按钮。调用方可根据需要把成功构造的结构替换进自己的工作区。

## 从程序生成数据

```java
import com.majortom.algorithms.core.metadata.GraphDirection;
import com.majortom.algorithms.structure.graph.Graph;
import com.majortom.algorithms.structure.graph.GraphData;
import com.majortom.algorithms.structure.graph.GraphInitializer;
import com.majortom.algorithms.structure.graph.GraphLink;
import com.majortom.algorithms.structure.initialization.DataGenerator;
import java.util.List;

DataGenerator<GraphData<Integer>> generator = () -> new GraphData<>(
    GraphDirection.UNDIRECTED,
    List.of(1, 2, 3),
    List.of(new GraphLink<>(1, 2, 5.0), new GraphLink<>(2, 3, 8.0))
);

GraphInitializer<Integer> initializer = new GraphInitializer<>();
Graph<Integer> graph = initializer.create(generator.generate());
```

## 初始化规则

- 图方向、顶点和边是独立于文件格式的领域数据。
- 不允许重复的顶点、重复或反向重复的无向边，以及引用不存在顶点的连接。
- 图边权必须是有限数值，允许负数以兼容其他图算法；Dijkstra 等算法自行约束非负权重。
- `GraphInitializer.initialize(existingGraph, data)` 要求方向一致，验证通过后才替换图状态。
- `ArrayInitializer` 复用现有数组的批量初始化，不伪造逐元素事件。
- JSON 解析和初始化是两步；文件读取失败不接触原结构，结构校验失败也不会替换工作区中的原结构。
- 业务类型可用 `TypeReference<GraphData<Location>>` 表达，但自定义 `Location` 类型必须具备 Jackson 可反序列化的构造方式。
- 从文件读写 GraphData/Array 的便利接口在 `client`，而非 `data-io` 或结构实现本身。
