# 注解驱动注册与动态类型分阶段改造方案

## 1. 目标

本次改造不重写算法、结构、Event、Timeline、Snapshot 或 Visualizer，而是重构“组件如何被发现、注册、匹配和实例化”这一层，使正式 Algorithm / Structure，以及后续 Practice，能够共享固定包内的自动发现机制。

核心路线：

```text
固定包扫描
    ↓
识别框架注解
    ↓
校验接口 / 泛型 / type / structure
    ↓
生成 Descriptor
    ↓
Registry
    ↓
Resolver
    ↓
Runtime
    ↓
现有 Event / Timeline / Reducer / Visualizer
```

明确边界：

- 只支持项目自身固定包内的类。
- 不支持外部 JAR 插件、第三方扩展包、动态 ClassLoader 扩展。
- 不引入 Annotation Processor，不生成 META-INF 索引。
- 不把算法实现强制泛型化；Integer/String/Long 算法可以继续分别实现。
- Structure 实现保持泛型复用，例如 `Array<T>`、`LinkedList<T>`、`Tree<T>`、`Graph<T>`。
- `ExecutionEvent / StructureEvent / ObservationEvent` Contract 不因注册系统改造而增加算法特化语义。
- Timeline、Recording、Replay、Statistics 语义保持不变。
- Snapshot 继续保持 UI-neutral。
- **GridMaze 及直接依赖 GridMaze 的网格迷宫算法暂不纳入本轮 type + structure + StructureResolver 动态化体系。**

### 1.1 GridMaze 排除范围

本轮明确排除：

```text
GridMaze
ArrayMazeGenerator
ArrayMazePathfinder
BfsArrayMazeGenerator
DfsArrayMazeGenerator
UnionFindArrayMazeGenerator
AStarArrayMazePathfinder
DfsArrayMazePathfinder
```

它们继续保持当前领域模型与执行方式，不为了统一注册模型去制造 `MazeStructure<Boolean>`、伪造 `Boolean` value type，或者改变 `GridMaze` 的不可变领域语义。

本轮对“Algorithm 必须声明 type + structure”的规则，仅约束能够自然映射到泛型 Structure Contract 的正式算法。

Graph-backed maze 算法如果天然使用 Graph Contract，可按 Graph 算法处理；本轮不为 Maze 专门增加任何特殊 Resolver 或 Binding 模型。

GridMaze 后续若需要统一，单独立项，不阻塞本轮改造。

## 2. 注解模型

### 2.1 Structure

结构实现通过注解声明稳定身份和 Contract：

```java
@Structure(
        id = "array",
        contract = ArrayStructure.class
)
public final class Array<T> implements ArrayStructure<T> {
}
```

一个实现允许对应多个逻辑结构 Contract，因此 `@Structure` 应支持重复标注。例如：

```java
@Structure(id = "linked-list", contract = LinkedStructure.class)
@Structure(id = "stack", contract = StackStructure.class)
@Structure(id = "queue", contract = QueueStructure.class)
public final class LinkedList<T>
        implements LinkedStructure<T>, StackStructure<T>, QueueStructure<T> {
}
```

注解只声明注册信息，不替代 Java interface。Registry 构建时必须验证 implementation 实际实现声明的 contract。

### 2.2 Algorithm

本轮纳入动态结构体系的 Algorithm 强制声明：

- 稳定 `id`
- 运行时值类型 `type`
- 所需结构 Contract `structure`

```java
@Algorithm(
        id = "quick-sort",
        type = Integer.class,
        structure = ArrayStructure.class
)
public final class IntegerQuickSort implements Sort<Integer> {
}
```

String 算法可以继续使用同一个 Array Structure：

```java
@Algorithm(
        id = "string-sort",
        type = String.class,
        structure = ArrayStructure.class
)
public final class StringSort implements Sort<String> {
}
```

目标关系：

```text
IntegerQuickSort
    type = Integer
    structure = ArrayStructure
            ↓
      Array<Integer>

StringSort
    type = String
    structure = ArrayStructure
            ↓
       Array<String>
```

Algorithm 不指定 `Array.class` 这类具体实现，只指定 `ArrayStructure.class` 这种 Contract；具体 implementation 由 `StructureResolver` 选择。

### 2.3 Practice

Practice 后续使用：

```java
@Problem(
        source = ProblemSource.LEETCODE,
        id = "1",
        title = "两数之和"
)
public final class TwoSum {

    @ProblemEntry
    public static int[] twoSum(int[] nums, int target) {
        ...
    }
}
```

`@ProblemEntry` 只声明执行入口，不承担 Trace、Visualizer 或 Event 语义。

Algorithm / Structure 注册改造稳定前，不实施 Practice UI。

## 3. Descriptor 模型

现有 Registry 把 family、valueType、id 编码进字符串：

```text
structure.array.Integer
algorithm.array.Integer.quick-sort
```

改造后，字符串 key 不再作为领域信息的主要载体。

建议：

```java
public record StructureDescriptor(
        String id,
        Class<?> contract,
        Class<?> implementation
) {
}
```

```java
public record AlgorithmDescriptor(
        String id,
        Class<?> valueType,
        Class<?> structureContract,
        Class<?> implementation
) {
}
```

后续 Practice 使用独立 `ProblemDescriptor`。

GridMaze 域不进入上述 `AlgorithmDescriptor -> StructureResolver` 动态结构匹配流程。

---

## 4. 扫描范围

Runtime Discovery 只扫描：

```text
com.majortom.algorithms.structure
com.majortom.algorithms.algorithm
com.majortom.algorithms.practice
```

第一轮只启用前两个包。

不要扫描整个 `com.majortom.algorithms`，避免 Client、Server、JavaFX Controller 等无关类进入候选集合。

新增统一：

```java
FrameworkClassScanner
```

职责仅为：

```java
List<Class<?>> scan(String rootPackage)
```

Scanner 不理解 Algorithm / Structure / Problem 语义。

上层由：

```text
StructureDiscovery
AlgorithmDiscovery
ProblemDiscovery
```

解释注解并生成 Descriptor。

GridMaze 相关类可以被 Scanner 看见，但本轮 AlgorithmDiscovery 不将其纳入 type + structure 动态注册结果；保持现有路径即可。

## 5. 注册校验原则

Annotation 不能成为绕过 Java 类型系统的手段。

### 5.1 Algorithm

```java
@Algorithm(
        id = "foo",
        type = String.class,
        structure = ArrayStructure.class
)
public final class Foo implements Sort<Integer> {
}
```

必须 fail-fast：

```text
annotation type = String
contract type   = Integer
```

同理：

```java
@Algorithm(
        id = "foo",
        type = Integer.class,
        structure = TreeStructure.class
)
public final class Foo implements Sort<Integer> {
}
```

必须拒绝，因为 `Sort<Integer>` 与声明的 `TreeStructure` 不一致。

### 5.2 Structure

```java
@Structure(
        id = "array",
        contract = ArrayStructure.class
)
public final class Foo {
}
```

如果 `Foo` 不实现 `ArrayStructure`，直接拒绝注册。

### 5.3 其他约束

- `id` 唯一。
- Algorithm id 使用稳定 kebab-case。
- concrete component 不允许 abstract / interface。
- `type` 使用包装类型，例如 `Integer.class`、`Long.class`，不使用 primitive class。
- implementation 必须满足框架可实例化条件。
- 冲突、无法解析、类型不一致全部 fail-fast，不静默覆盖。
- GridMaze 排除项不套用上述 type + structure 校验规则。

# 6. 分阶段实施

## Phase 0：基线锁定与映射清单

### 工作

1. 导出现有 Structure registrations。
2. 导出现有 Algorithm registrations。
3. 记录现有 Workbench 可见算法集合。
4. 对本轮纳入范围的 Algorithm 明确 `id / type / structure`。
5. 对本轮纳入范围的 Structure 明确 `id / contract / implementation`。
6. 明确 GridMaze 排除清单，迁移过程中不得顺手重构。
7. 保留 Quick Sort / Graph BFS / KMP / Maze probe 作为整体回归基线；Maze probe 只验证没有被本轮改坏，不要求它迁入新 Resolver。

### 验收

```text
迁移前 registry snapshot 已保存
in-scope algorithm 注解映射完整
in-scope structure 注解映射完整
GridMaze exclusion list 固定
Maze 行为保持原样
```

## Phase 2：固定包 Scanner + Annotation Discovery

新增：

```text
FrameworkClassScanner
StructureDiscovery
AlgorithmDiscovery
```

Discovery 输出 Descriptor，不再输出拼接 registry key。

本阶段双轨运行：

```text

        +
新 Annotation Discovery
```

只比较本轮纳入范围的注册结果；GridMaze 相关旧注册不参与“新旧集合必须完全相等”的要求。

对现有 Structure / Algorithm 加注解，算法内部实现不改。

### 验收

```text
in-scope 旧注册集合 == 新注解注册集合
Algorithm ID 不变化
Structure 可用能力不减少
Quick Sort probe 通过
Graph BFS probe 通过
KMP probe 通过
Maze probe 仍通过，但继续走原路径
```

## Phase 3：Descriptor Registry + StructureResolver

新增/重构：

```text
ComponentRegistry
StructureResolver
```

典型流程：

```text
algorithmId
    ↓
AlgorithmDescriptor
    ↓
valueType = String.class
structureContract = ArrayStructure.class
    ↓
StructureResolver
    ↓
StructureDescriptor
    ↓
Array.class
```

Registry 不再为同一个泛型实现维护：

```text
structure.array.Integer
structure.array.Long
structure.array.String
```

三份 registration，而是：

```text
StructureDescriptor(array, ArrayStructure.class, Array.class)
```

运行上下文另外携带 valueType。

### 验收

- Resolver 能根据 AlgorithmDescriptor 找到兼容 Structure。
- 同一个 `Array.class` 能建立 Integer/String/Long runtime context。
- 类型不兼容 fail-fast。
- 调用方不再需要拼接 registry key。
- GridMaze 不进入 StructureResolver。

---

## Phase 4：切换正式注册源，清理旧注册机制

对本轮纳入范围，逐步退出：

```text
structures/src/main/resources/META-INF/algorithms.factories
algorithms/src/main/resources/META-INF/algorithms.factories 中的普通结构算法条目
旧 AlgorithmModuleDiscovery 的类名推 ID 逻辑
旧 ModuleDiscovery ServiceLoader 路径（若对 in-scope 组件已无用途）
```

**注意：GridMaze 排除项允许暂时保留最小 legacy registration 路径。** 不为了追求“一个旧文件都不剩”而把 Maze 强行纳入本轮模型。

目标是：普通 Structure / Algorithm 已完全由 Annotation Discovery 驱动；GridMaze 的 legacy path 明确、隔离、可识别。

### 验收

- in-scope 组件启动只依赖 Annotation Discovery。
- 无 class-name-derived algorithm id。
- 重命名 in-scope algorithm implementation class 不改变稳定 ID。
- GridMaze 仍可正常使用。

---

## Phase 5：Client 从字符串 key 切换到 Descriptor

主要涉及：

```text
MainController
BaseController
AlgorithmCatalog
WorkbenchModules
ArrayController
LinkedListController
LinearStructureController
TreeController
GraphController
StringController
```

GridMaze/MazeController 不要求在本阶段迁到 StructureResolver；仅在公共 Registry API 变化导致编译需要时做最小适配。

禁止继续在 in-scope 路径中：

```java
module("algorithm.array.Integer." + algorithmId, Sort.class)
```

改为：

```text
algorithmId
  ↓
AlgorithmDescriptor
  ↓
Registry.createAlgorithm(...)
```

本阶段重点是消除普通结构算法的字符串 registry key 依赖，不要求马上完成动态 ValueType UI。

### 验收

- Workbench 现有功能与迁移前一致。
- Snapshot / Inspector / Timeline / Replay 无回归。
- Algorithm selector 来自 Descriptor Registry。
- in-scope Controller 不再拼接 `algorithm.array.Integer.` 等 key。
- Maze UI 行为不变。

# 7. 明确不做的事情

本轮不做：

- 外部 JAR / Plugin SPI。
- Annotation Processor / generated index。
- Spring/DI Container。
- `@Inject` / `@Component` 式生命周期管理。
- 将 Algorithm 强制泛型化。
- UniversalStructure/ObjectGraph。
- Event Contract 算法特化。
- 在 Annotation 中描述 Visualizer、Reducer、Snapshot、I18N label。
- 在 Annotation 中塞测试数据。
- 为 GridMaze 设计 `MazeStructure<Boolean>`。
- 为 GridMaze 引入 StructureRole / 多 Binding / INPUT-OUTPUT binding 模型。
- 为了形式统一而修改 GridMaze 现有领域 API。

# 8. 预计改动规模

排除 GridMaze 后，完整做到 Phase 8，预计：

```text
核心 Registry / Discovery       8～12 个文件
Structure 注解迁移              6～9 个文件
Algorithm 注解迁移             约 8～13 个文件
Client Registry 消费             6～10 个文件
Client ValueType 泛化           10～16 个文件
Server                           1～3 个文件
Tests / Docs                     8～12 个文件
```

存在文件重叠，预计最终约：

```text
30～45 个 Java 文件发生有效修改
8～12 个新的框架类
约 1800～3200 行有效 diff（包含删除和测试）
```

风险等级：中。

风险主要集中在 Client 中已有的 Integer 假设，而不是 Structure/Event/Timeline 核心。排除 GridMaze 后，不再需要为了 Maze 引入额外 Binding 抽象，整体风险和设计复杂度都有所下降。

# 10. 最终架构目标

```text
                     Fixed Package Scanner
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
     @Structure          @Algorithm          @Problem
          │                   │                   │
          ▼                   ▼                   ▼
 StructureDiscovery   AlgorithmDiscovery   ProblemDiscovery
          │                   │                   │
          └───────────────────┼───────────────────┘
                              ▼
                      Descriptor Registry
                              │
                              ▼
                           Resolver
                              │
                  ┌───────────┴───────────┐
                  ▼                       ▼
          Structure Instance        Algorithm/Problem
                  │                       │
                  └───────────┬───────────┘
                              ▼
                            Runtime
                              │
                              ▼
             StructureEvent / ObservationEvent
                              │
                              ▼
                   Timeline / Recording
                              │
                              ▼
                    Reducer / ViewState
                              │
                              ▼
                         Visualizer
```

GridMaze 是本轮明确的领域例外：继续使用既有领域 API 与执行路径，不进入上述 StructureResolver 动态类型主链。

最终原则：

> Annotation 负责声明身份与兼容信息；Interface 负责行为契约；Descriptor 保存运行时 metadata；Resolver 负责匹配普通泛型结构实现；Event/Timeline/Visualizer 继续只表达真实执行事实和结构状态。GridMaze 暂不为了形式统一而进入该抽象。
