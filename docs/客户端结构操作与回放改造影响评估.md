# Client Structure / Replay V2 现状

本文记录当前已经落地的客户端边界，不再描述旧 Provider/Runner 架构。

## Structure 模式

当前一等结构：Array、LinkedList、Stack、Queue、Tree、Graph、HashTable、String。

结构操作直接作用于真实领域结构，并通过 ExecutionRuntime 记录必要的结构事件。Structure Timeline 过滤 Runtime 生命周期和 LogEvent，只展示结构领域历史。

## Algorithm 模式

有算法的结构：

- Array：Insertion / Selection / Quick / Heap sort
- Tree：AVL command execution
- Graph：BFS
- String：KMP

Maze 保留独立的 generation/pathfinding 算法工作台。

Structure-only 模块不会显示伪算法入口。

## Snapshot

Snapshot 数据属于 core，UI ViewState 不进入 Snapshot。

Array / Tree / Graph / String 的保存快照可以：

1. 恢复到 Structure 模式；
2. 单独选为 Algorithm 输入。

第二种操作不会修改当前结构，也不产生 SnapshotRestored 结构事件。

Tree 使用稳定 nodeId 和完整拓扑恢复算法输入。

## Live execution 与 replay

```text
ExecutionRuntime -> authoritative EventEnvelope stream
                   ├── Recording / Statistics / Log
                   └── JavaFX live playback -> Reducer -> ViewState

Recorded events -> ReducedEventTimeline -> PlaybackController
```

Runtime pause/resume/live-step/cancel 与 replay step 是两个不同概念。

动画播放 delay 不反压算法 worker。Runtime total duration 在算法执行结束时冻结，不包含 JavaFX 播放等待。

## Reducer

Reducer/Reduction/EventImportance/visualFrame 全部属于 client presentation 层。

Reducer 只负责把领域 EventEnvelope 转换成不可变 ViewState；不能反向修改算法或领域结构。

## 维护注意

- 不把 ViewState 放进 core。
- 不把动画颜色/毫秒数编码到领域事件。
- 不通过 Thread.sleep 控制算法可视化速度。
- 不恢复 ProviderCatalog / DefaultAlgorithmRunner / AlgorithmContext。
- 新结构首先明确领域操作和 Snapshot 数据，再接 Workbench。
