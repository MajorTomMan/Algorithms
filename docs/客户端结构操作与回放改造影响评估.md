# Client 工作区与回放说明

## 1. 工作区模型

客户端使用一个统一工作区。

工作区包含两种互斥模式：

```text
Structure
Algorithm
```

两种模式共享模块选择和可视化区域，但职责不同。

- Structure：维护真实数据结构。
- Algorithm：使用 Snapshot 作为输入运行算法。

客户端不会同时维护两份可编辑结构。

## 2. 模块

工作区提供：

- Sort / Array
- LinkedList
- Stack
- Queue
- Maze
- Tree
- Graph
- HashTable
- String

其中 LinkedList、Stack、Queue、HashTable 是 structure-only 模块，不显示算法执行入口。

具有算法模式的模块包括：

### Array

- Insertion Sort
- Selection Sort
- Quick Sort
- Heap Sort

### Tree

- AVL commands

### Graph

- BFS

### String

- KMP

### Maze

- BFS generation
- DFS generation
- Union-Find generation
- Graph BFS generation
- A* pathfinding
- DFS pathfinding

## 3. Structure 模式

Structure 模式持有模块的唯一真实结构。

主要能力：

- 新增/删除/修改结构元素
- 结构可视化
- Snapshot 保存
- Snapshot 恢复
- Structure History

结构操作通过 `ExecutionRuntime` 执行，因此重要结构动作会产生领域事件。

Structure History 主要显示结构语义事件，不把 Runtime 生命周期和普通日志混在同一列表中。

## 4. Snapshot

Snapshot 表示结构的完整状态。

Snapshot 数据定义在 core，而不是 JavaFX ViewState。

### 4.1 保存

用户保存 Snapshot 后，Snapshot 卡片进入保存列表，同时记录 SnapshotCreated 语义。

### 4.2 恢复结构

“恢复结构”会用 Snapshot 替换 Structure 中的真实结构，并记录 SnapshotRestored。

### 4.3 作为算法输入

对支持算法的模块，保存的 Snapshot 可以选择为 Algorithm 输入。

该操作：

- 不修改 Structure。
- 不触发结构恢复。
- 不改变 Snapshot 本身。
- Algorithm 运行时创建临时领域输入。

Algorithm 模式顶部会显示输入来源：

```text
当前结构快照
已保存快照 <id>
算法参数
```

## 5. Algorithm 模式

进入 Algorithm 模式后：

1. 选择算法。
2. 设置参数。
3. 确认算法输入来源。
4. 预览输入 Snapshot。
5. 启动执行。

运行前如果没有算法帧，画布显示所选 Snapshot 的初始投影。

算法结束后，运行结果保存在算法 Timeline 中，不回写 Structure。

如果 Algorithm 锁定的是保存 Snapshot，之后修改当前 Structure 不会改变这次算法输入或已生成的回放记录。

## 6. Maze 输入与结果

Maze 生成器主要使用算法参数创建结果。

生成完成后，结果属于 Algorithm 模式。用户执行“应用结果到结构”后，结果才成为 Structure 中的真实 Maze。

Maze Pathfinder 使用 Maze Snapshot 作为输入，可以选择：

- 当前 Maze Snapshot；或
- 已保存 Maze Snapshot。

因此 Maze 的生成、寻路和结构编辑之间保持明确边界。

## 7. Live Execution

Algorithm 执行由 `ExecutionRuntime` 管理。

运行控制包括：

- Run
- Pause
- Resume
- Live Step
- Cancel / Reset

运行时工作区和模块导航保持锁定，避免切换后同一个可视区域同时接收不同模块或不同模式的更新。

### Live Step

运行暂停后，Forward 按钮执行 Runtime Step。

每次 Step 放行下一个领域事件，然后保持暂停。

运行结束后，同一个 Forward 按钮用于 Timeline Replay 的下一帧。

Backward 始终属于 Replay。

## 8. Runtime 与 Playback

算法执行和动画播放是两个独立过程：

```text
ExecutionRuntime
      ↓
authoritative EventEnvelope stream
      ├── Recording
      ├── Statistics
      ├── Logging
      └── JavaFX playback queue
                 ↓
              Reducer
                 ↓
              ViewState
                 ↓
             Visualizer
```

JavaFX 动画延迟不会阻塞算法 worker。

执行会暴露两个完成状态：

- `runtimeCompletion`：领域执行已经结束。
- `presentationCompletion`：实时播放队列已经完成。

UI 的最终收尾使用 presentation completion；运行统计使用 runtime completion。

## 9. Reducer 与 ViewState

Reducer 负责把 EventEnvelope 投影为不可变 ViewState。

Reducer 只处理 presentation：

- 高亮状态
- 当前指针
- 已访问节点
- 交换后的展示
- 算法结果视图

Reducer 不修改真实领域结构，也不参与核心算法计算。

ViewState 只存在于 client。

## 10. Timeline Replay

执行完成后，EventEnvelope 会形成可回放 Timeline。

支持：

- backward
- forward
- seek
- replay

Replay 通过重新归约已记录事件生成 ViewState，不重新执行算法。

因此：

```text
Live execution = 执行算法并产生事件
Replay         = 消费已有事件并恢复展示状态
```

## 11. Statistics 与 Log

Algorithm 模式显示事件统计和日志。

Statistics 来源于 Runtime 事件记录，包括：

- total events
- domain events
- lifecycle events
- domain metrics
- runtime duration

Client 还可以维护 presentation 信息，例如 visual frame 数和 playback duration。

LogEvent 与普通算法事件共用 EventEnvelope，但日志视图和结构历史分别按语义过滤。

## 12. 响应式布局

应用始终保持单工作区模型。

窗口变窄时：

- 左右辅助区域可以缩小。
- Snapshot 面板保持可用。
- Structure / Algorithm 仍通过模式切换进入。
- 不同时显示两套工作区。

Snapshot 是 Structure 和 Algorithm 之间的数据连接点，因此不会因窄屏布局被完全隐藏。

## 13. Controller 职责

模块 Controller 主要负责：

- 结构操作编排
- Snapshot 捕获与恢复
- 算法输入 Snapshot 选择
- Algorithm operation 创建
- ViewState 初始化
- UI 参数读取

公共执行、播放和回放能力由共享 client execution/playback 层处理。

新增模块时，应优先复用这些公共能力，模块 Controller 只保留自身领域差异。
