# 客户端结构操作与回放改造影响评估

## 1. 结论

这次改造值得做，但重点应放在 **JavaFX 工作区和数据流**，不应先重写 `core` 的执行协议。

目标界面分成两个入口：

- **结构**：选择数组、链表、树、图、迷宫等结构，进行增删查改或结构化编辑，并保存为一个不可变快照；
- **算法**：选择一个支持该结构的算法，读取快照，执行并按事件逐帧回放，显示统计和日志。

这样可以让“编辑数据”和“运行算法”互不混淆，也能继续复用现有的事件、`EventReducer`、播放控制和统计链路。

改造影响主要集中在 `client`。`core` 的通用运行时可以保持稳定；`algorithms` 只有在新增链表算法、结构操作动画或新的事件类型时才需要扩展；`server` 不需要依赖任何 JavaFX 类。

## 3. 当前实现和调用链

### 3.1 JavaFX 外壳

`MainControls.fxml` 当前使用 `BorderPane`：

```text
top     顶部标题和模块导航
left    settingsPanel，装载当前模块的控制面板
center  visualizationViewport，装载可视化器
right   diagnosticsPanel，统计和日志
bottom  播放按钮、延迟滑块、时间轴
```

模块控制面板通过以下链路动态装载：

```text
MainController
  -> ModuleRegistry
  -> AlgorithmModuleDefinition
  -> BaseModuleController.loadControlPanel()
  -> 对应的 Sort/Tree/Graph/MazeControls.fxml
```

当前左右面板是 `BorderPane` 的固定区域，窄屏时主要依靠隐藏和重新放回面板来适配，并没有真正的覆盖式抽屉。因此面板打开后会继续挤压中心画布。

### 3.2 算法执行和回放

```text
模块 Controller
  -> BaseController.startAlgorithm()
  -> ClientExecutionService
  -> LocalAlgorithmExecution
  -> core.DefaultAlgorithmRunner
  -> ExecutionEvent
  -> EventReducer<ViewState>
  -> BaseVisualizer.render(ViewState)
```

事件记录由 `BoundedExecutionEventStore` 保存，`PlaybackController` 和 `ReducedEventTimeline` 负责播放、暂停、定位和单步。实时统计已经通过 `ExecutionStatistics` 回调接入客户端，执行结束后再补齐最终的时间和资源摘要。

### 3.3 当前模块能力

- **排序**：数组数据生成，以及添加、删除、查找、修改等本地输入编辑；排序算法消费不可变的 `IntegerSortInput`。
- **树**：AVL 插入、删除、查找和修改入口；修改采用删除旧值再插入新值的命令语义。
- **图**：节点和有向边增删、节点查找、遍历起点设置；当前 `IntEdge` 是无权边，不应在界面继续暴露权重输入。
- **迷宫**：结构选择、生成、求解、尺寸调整和重置；迷宫更适合“编辑单元格、设置起点终点、生成、求解”，不适合机械套用通用 CRUD。
- **链表**：`algorithms` 中已有基础链表类，但当前没有和目录、事件、`EventReducer` 对接的正式链表遍历算法，因此链表遍历动画属于后续算法扩展，不是单纯改 FXML 就能完成。

## 4. 目标工作区模型

建议将主界面整理为以下结构：

```text
Root VBox
├── AppBar
│   ├── 项目标题
│   ├── 结构 / 算法入口
│   └── 设置、语言和帮助
├── Workspace StackPane
│   ├── StructurePanel          结构选择、输入和操作
│   ├── VisualizationViewport  中央画布、缩放、平移、适应窗口
│   ├── DiagnosticsPanel        统计、当前事件、日志
│   ├── 左侧覆盖式抽屉
│   └── 右侧覆盖式抽屉和遮罩层
└── PlaybackDock
    ├── 播放、暂停、重置、前后单步
    └── 时间轴、速度和当前帧
```

数据流保持单向：

```text
结构操作
  -> 当前结构编辑模型
  -> 校验
  -> 新快照
  -> 算法输入
  -> ExecutionEvent
  -> EventReducer
  -> ViewState
  -> 渲染和回放
```

结构操作和算法事件要分开：

- 结构操作默认只更新输入模型并生成新快照，不自动伪造算法回放帧；
- 算法运行时只读取快照，运行期间锁定结构编辑，避免输入和事件序列不一致；
- 如果以后要把“插入数组”“移动链表指针”本身做成动画，再为这些操作定义专门的领域事件和 reducer。

## 6. 分阶段改造目标

### 阶段一：冻结协议和边界

目的：避免 UI 重构过程中顺手改变算法执行语义。

产出：

- 确定结构快照、算法输入、执行记录三种对象的边界；
- 明确结构操作默认不产生算法帧；
- 固定 `ExecutionEvent`、`EventReducer`、统计字段和 `runId` 规则；
- 列出每个结构支持的操作和输入限制。

### 阶段二：重建 JavaFX 工作区外壳

目的：解决固定左右栏、操作区挤压画布和小屏溢出问题。

产出：

- 顶部结构/算法入口；
- 中央可缩放、可平移的 viewport；
- 左右覆盖式抽屉，打开抽屉时使用遮罩，不改变画布尺寸；
- 宽屏、中等窗口和窄屏三种布局策略；
- 操作面板和日志区域可独立滚动。

### 阶段三：常驻结构操作面板

目的：让增删查改成为结构工作区的一等操作，而不是弹窗。

产出：

- 四个模块保留自己的 FXML 和 Controller；
- 统一输入框、按钮、分组标题和校验提示的视觉规范；
- 结构操作成功后生成新快照并清理旧执行记录；
- 算法执行中锁定编辑控件，执行结束后恢复。

不建议此阶段抽象一个强行通用的 `CrudPanel`。数组、树、图和迷宫的操作语义不同，先统一样式和布局容器即可。

### 阶段四：可视化区域适配数据规模

目的：让大数组、深树、大图和大迷宫仍然可读。

产出：

- 排序：元素过多时聚合或抽样，避免每个元素都绘制完整文字和装饰；
- 树：缩放、平移、局部聚焦，避免节点半径无限缩小；
- 图：保留平移、缩放、适应窗口，必要时隐藏部分标签；
- 迷宫：大网格使用缩放和局部查看；
- UI 本身不整体缩放，只缩放中央数据视图。

### 阶段五：统一统计、日志和回放显示

目的：让实时执行、完成摘要和回放状态的含义一致。

产出：

- 统计卡片显示事件数、帧数、操作计数、输入规模、耗时和资源信息；
- 运行中显示事件计数和事件跨度，结束后显示最终 CPU/内存采样结果；
- 日志采用有界或虚拟化列表，避免大事件流导致文本区域无限增长；
- 时间轴支持播放、暂停、单步、定位和终态重建。

### 阶段六：补充结构算法和逐帧操作动画

目的：扩展“基于结构验证算法”的能力，而不是只增加按钮。

按需扩展：

- 链表遍历：定义输入、遍历事件、输出和 `LinkedListEventReducer`；
- 数组插入动画：定义输入编辑事件和对应的数组视图状态；
- 树最长路径、交换子树：定义访问、比较、重连和完成事件；
- 图的 BFS/DFS 或最短路径：定义节点、边、队列和回溯事件。

这一阶段才修改 `algorithms` 和必要的 `core` 事件类型。若只做结构编辑，不需要改变核心执行协议。

### 阶段七：整理和验证

目的：确认重构没有破坏现有四类可视化和未来 server 的复用边界。

产出：

- FXML 加载、事件方法、国际化键和 CSS 类完整对应；
- 宽屏和窄屏窗口手工验收；
- 大规模输入下的绘制帧率和事件存储上限记录；
- 客户端构建、现有测试、XML 校验和差异检查通过；
- 文档、启动命令和打包命令同步更新。

## 7. 主要风险和控制方式

### 7.1 布局重构后控件再次溢出

控制：操作区域使用 `GridPane`、可换行 `FlowPane` 或独占整行按钮；抽屉内部保持滚动；不依赖按钮固定宽度承载中文文本。

### 7.2 结构编辑和算法运行使用了不同数据

控制：算法只接收不可变快照；运行中禁用结构编辑；新编辑操作创建新快照并使旧执行记录失效。

### 7.3 把结构操作误当成算法事件

控制：默认把 CRUD 作为输入准备过程；只有确实需要动画时才增加领域事件，不在 Controller 中伪造 `ExecutionEvent`。

### 7.4 大数据导致 JavaFX 卡顿或内存增长

控制：事件存储有界、日志有界、渲染按规模聚合；实时统计可以节流刷新 UI，但不能丢失权威事件。

### 7.5 为了通用化过度抽象

控制：先共享布局容器、样式和状态接口，不提前创建涵盖所有结构的万能 CRUD 组件。至少出现三个稳定相同的表单后再抽公共组件。

### 7.6 国际化和 FXML 回调遗漏

控制：新增控件同时补充中英文资源；构建前做 FXML XML 校验、事件方法扫描和资源键集合检查。

## 8. 不在本次范围内的内容

- 不改 `core` 的泛型执行接口和事件封装语义；
- 不在本次改造中实现 Spring Boot 服务端接口、SSE、数据库或鉴权；
- 不在 JavaFX 内引入网络 JSON 作为本地事件传输格式；
- 不在 Spring Boot 主进程中直接执行用户提交的任意代码；
- 不把 `other` 练习代码纳入生产算法目录；
- 不为了假设中的未来需求引入消息队列、数据库或插件系统。

## 9. 验收和回滚

建议每个阶段独立提交，至少验证：

```bash
mvn -pl client -am test -q
mvn -pl client -am -DskipTests compile -q
git diff --check
```

另外手工检查：

- 宽屏：操作区、画布、统计区同时可见；
- 中等窗口：抽屉打开后画布不被重新挤压；
- 窄屏：操作面板和统计面板可独立打开、滚动和关闭；
- 数组、树、图、迷宫均能从结构编辑进入算法执行和回放；
- 运行中统计持续变化，结束后最终摘要正确；
- 输入修改后旧时间轴不会误用于新快照。

回滚时按阶段回退对应的 `client` FXML、Controller 和 CSS 提交即可；不应通过覆盖 `core` 或删除用户已有改动来回滚。若新增了算法事件，先保留协议版本和 Provider 映射，再回退对应界面入口。

## 10. 尚未确认的信息

- 最小支持窗口宽度和三个响应式断点的具体数值；
- 结构操作是否需要进入同一条算法时间轴，还是只作为快照编辑记录；
- 排序、树、图和迷宫的最大演示规模；
- 链表是否作为正式算法模块加入 `ProviderCatalog`，以及首个支持的遍历算法；
- 是否需要把执行记录导出格式作为未来 server 的正式协议。

这些信息不影响先做工作区外壳和结构操作面板，但会影响后续事件模型和数据规模策略。
