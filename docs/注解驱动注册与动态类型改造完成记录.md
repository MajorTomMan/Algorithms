# 注解驱动注册与动态类型改造完成记录

基线：`dev@3b8d85f4afdde98dff0cce8ce1268991747e46f2`

本记录对应《注解驱动注册与动态类型分阶段改造方案》的最终落地状态。后续明确采用“不留兼容”的决策，因此 Maze 与原方案中允许保留 legacy path 的描述相比做了更彻底的收口：Maze 算法进入注解发现，但不伪造 `MazeStructure<Boolean>`，`GridMaze` 仍保持领域模型，不进入 `StructureResolver`。

## Phase 0～5：注册主链

- Structure / Algorithm 使用固定包扫描 + 注解发现。
- `AlgorithmDescriptor` / `StructureDescriptor` / `ComponentRegistry` / `StructureResolver` 成为正式注册和解析入口。
- Client 使用稳定 algorithm / structure id，不再拼接 `algorithm.array.Integer.*`、`structure.array.Integer` 等 registry key。
- `ModuleLoader`、`ModuleRegistry`、`ModuleDiscovery`、`AlgorithmModuleDiscovery`、`META-INF/algorithms.factories` 和对应 ServiceLoader 资源全部退出。
- Maze 算法也由 `@Algorithm` 发现；无结构 Contract 的算法明确使用 `Void.class`，Resolver 对其 fail-fast。

## Phase 6：Array 动态 ValueType POC

- 新增 `VisualValue`，展示层不再把 Array value 写死为 `Integer`。
- 新增 `StringInsertionSort`：`type=String.class`、`structure=ArrayStructure.class`。
- Integer 与 String 算法都解析到同一个 `Array.class`。
- Integer/String 都通过相同 `ArrayEventReducer` 进行真实 Timeline replay。
- `SequenceSnapshot<String>` 可作为算法输入恢复。

## Phase 7：Linked / Tree / Graph 值泛化

- `LinkedListViewState`、`TreeViewState`、`GraphViewState` 的 value 投影统一为 `VisualValue`。
- 对应 Reducer 删除 `(Integer)` 强制转换。
- 对应 Visualizer 只消费 `VisualValue.text()`。
- index、node id、parent/children、left/right、vertex/edge 等拓扑语义保持原有强类型。
- Controller 仍可保持当前 Integer 编辑业务边界；展示/回放主链已经不依赖 Integer，因此新增其他 value type 不需要修改 Event Contract 或 Visualizer 拓扑模型。

## Phase 8：Server

- Server Registry API 使用稳定 algorithm id + `ComponentRegistry`。
- Transport metadata 与 implementation registry 解耦。
- 不引入动态 REST request schema。

## Phase 9：Practice / LeetCode

新增正式 Practice Runtime：

- `@Problem`
- `@ProblemEntry`
- `ProblemDescriptor`
- `ProblemDiscovery`
- `PracticeProblemRegistry`
- `PracticeRunner`
- `PracticeWorkerLauncher`
- immutable `PracticeRecording`

第一批接入 LeetCode 35（搜索插入位置）和 70（爬楼梯）。

可视化执行使用独立 Worker JVM + JDI：

1. Host 完成固定包 Discovery，只向 Worker 传递已经解析好的 class/method metadata 和参数；Worker 不二次扫描。
2. Worker 执行真实用户代码。
3. JDI 只记录实际发生的 source line、locals、异常和对象字段事实，不预测、不修正算法。
4. Worker 正常退出后 recording 仍是不可变可回放数据。
5. 超时只终止 Worker，不拖死 Workbench；已经记录的帧继续保留。

覆盖：

- 注册校验和重复 ID fail-fast。

最终要求：

```text
mvn test           -> BUILD SUCCESS

```

## 最终架构

```text
Fixed Package Scanner
        │
 ┌──────┼────────┐
 ▼      ▼        ▼
@Structure @Algorithm @Problem
 │        │        │
 ▼        ▼        ▼
Discovery / Descriptor
        │
        ▼
Registry / Resolver
        │
        ▼
Runtime
        │
        ├── formal Algorithm -> StructureEvent / ObservationEvent
        │                         -> Timeline -> Reducer -> ViewState -> Visualizer
        │
        └── Practice -> isolated Worker JVM -> JDI factual recording -> Workbench Replay
```

核心边界不变：Event 表达事实，Snapshot 保持 UI-neutral，Visualizer 不推断算法语义，Practice 的错误程序状态也必须忠实记录和回放。
